# Deploy + WhatsApp — step by step for the review

Total time: **~60 minutes.** Do them in order; each step needs the one before it.
Have your phone with WhatsApp ready.

Everything below uses **free tiers**. No card is needed for Render, Vercel or
Meta's WhatsApp Cloud API.

---

## What the WhatsApp chatbot already does (nothing to build)

A customer messages your number and gets an automatic reply. Built and tested:

| Customer sends | Bot does |
|---|---|
| Any problem ("my refund hasn't arrived") | Raises a ticket, classifies it, replies with the reference `SD-nnnn` |
| Another message while a ticket is open | Adds it to that ticket, confirms |
| `STATUS` | Lists their open tickets |
| `HELP` | Shows the commands |
| `NEW my other problem` | Raises a separate ticket |
| `CLOSE` | Closes their resolved ticket, or explains why it can't |
| *(agent replies in the web app)* | **Reply is delivered to their WhatsApp** as plain text |

You only need to connect a real number. That is step 4.

## Step 1 — Database + API on Render  (~15 min)

1. Go to **https://render.com** → sign up with GitHub.
2. Dashboard → **New +** → **Blueprint**.
3. Select the repo **ItzGOLLY/servicedesk-ai**, branch **main**.
4. Render reads `render.yaml` and shows two resources: `servicedesk-db` and
   `servicedesk-api`. Click **Apply**.
5. It will ask for the values marked `sync: false`. Fill in:

| Variable | Put |
|---|---|
| `CORS_ORIGIN` | `http://localhost:5173` for now — **you will change this in step 3** |
| `AI_API_KEY` | leave blank |
| `EMBEDDING_API_KEY` | leave blank |
| `WHATSAPP_ACCOUNT_SID` | leave blank — **step 4** |
| `WHATSAPP_AUTH_TOKEN` | leave blank — **step 4** |
| `WHATSAPP_FROM_NUMBER` | leave blank — **step 4** |
| `WHATSAPP_WEBHOOK_URL` | leave blank — **step 4** |

   JWT secrets are generated by Render automatically. Blank AI/WhatsApp values
   mean the offline providers run — everything still works.

6. Wait for the build (~4 min). Migrations run automatically every time the API
   starts (`npm run migrate && npm start`).
7. Copy the API URL. It looks like `https://servicedesk-api-xxxx.onrender.com`.
   **Write it down — you need it three more times.**
8. Check it:
   ```
   https://servicedesk-api-xxxx.onrender.com/api/health
   ```
   Must show `"database": "connected"`.

9. **Seed the demo accounts** (Render's Shell tab is not available on the
   free plan, so run this from your laptop against the cloud database):

   - Render dashboard → `servicedesk-db` → **Connect** → copy the
     **External Database URL** (starts with `postgresql://`).
   - In the repo, in a terminal:
     ```
     cd backend
     DATABASE_URL='<paste external url>' DATABASE_SSL=true \
     JWT_ACCESS_SECRET=x JWT_REFRESH_SECRET=x npm run seed
     ```
     (`JWT_*` just need to be non-empty for the config loader; they are not
     used by the seed.) This creates `admin@servicedesk.ai` / `Admin@12345`
     and the others. It is safe to run twice.

**If the build fails:** click Logs. The most likely cause is the free Postgres
taking a minute to come up — click **Manual Deploy → Deploy latest commit**.

## Step 2 — Frontend on Vercel  (~10 min)

1. Go to **https://vercel.com** → sign up with GitHub.
2. **Add New → Project** → import **ItzGOLLY/servicedesk-ai**.
3. Settings on the import screen:

| Setting | Value |
|---|---|
| Framework Preset | **Vite** |
| Root Directory | click **Edit** → `frontend` |
| Build Command | `npm run build` (default) |
| Output Directory | `dist` (default) |

4. Open **Environment Variables** and add **one**:

| Name | Value |
|---|---|
| `VITE_API_BASE_URL` | `https://servicedesk-api-xxxx.onrender.com/api` ← your step 1 URL **+ `/api`** |

   The `/api` on the end matters.

5. **Deploy**. Wait ~2 min.
6. Copy the frontend URL, e.g. `https://servicedesk-ai-xxxx.vercel.app`.

---

## Step 3 — Let the frontend talk to the API  (~3 min)

Login will fail with a CORS error until you do this.

1. Render dashboard → `servicedesk-api` → **Environment**.
2. Edit `CORS_ORIGIN` → set to your Vercel URL **exactly**:
   ```
   https://servicedesk-ai-xxxx.vercel.app
   ```
   No trailing slash. `https`, not `http`.
3. **Save** → Render redeploys (~2 min).

**Test:** open your Vercel URL → sign in as `admin@servicedesk.ai` /
`Admin@12345`. If it works, steps 1–3 are done.

## Step 4 — Real WhatsApp via Meta's Cloud API  (~25 min, free)

Meta's test number sends real free-form replies inside the 24-hour window a
customer's own message opens — which is always the case here, because the
customer writes first. Up to 5 phones can be verified as recipients.

> **Why not Twilio?** A Twilio *trial* account refuses free-form WhatsApp text
> on every sender, sandbox included (error 21654, "ContentSid Required"), and
> lifting that needs a ~$20 top-up. The Twilio provider is still in the code
> (`WHATSAPP_PROVIDER=twilio`) for an upgraded account.

### 4a — Create the app

1. **https://developers.facebook.com** → log in with a Facebook account →
   **Get Started** and register as a developer if asked.
2. **My Apps → Create App** → use case **Other** → type **Business** → name
   `ServiceDesk AI` → Create. If it asks for a Business Portfolio, create one
   with any name.
3. On the app dashboard → **Add product → WhatsApp → Set up**. Meta creates a
   test WhatsApp Business account with a test sender number.

### 4b — Collect the five values

| Value | Where |
|---|---|
| **Phone number ID** | WhatsApp → **API Setup** — under the test "From" number |
| **Test number** (e.g. `+1 555 …`) | Same place — the "From" number |
| **Access token** | Same page → **Generate** (temporary, **expires in 24 h** — see 4f) |
| **App Secret** | **App settings → Basic → App Secret → Show** |
| **Verify token** | You invent it, e.g. `servicedesk-verify-2026` |

Still on **API Setup**, under **To** → **Manage phone number list** → add your
phone (+91…) → enter the OTP WhatsApp sends → verified. Add your teammate too.

### 4c — Set Render **before** touching the webhook

Render → `servicedesk-api` → **Environment**:

| Variable | Value |
|---|---|
| `WHATSAPP_PROVIDER` | `meta` |
| `WHATSAPP_ACCESS_TOKEN` | the token from 4b |
| `WHATSAPP_PHONE_NUMBER_ID` | the Phone number ID |
| `WHATSAPP_APP_SECRET` | the App Secret |
| `WHATSAPP_VERIFY_TOKEN` | your invented string |
| `WHATSAPP_FROM_NUMBER` | the test number as `+1555…` (display only) |

Save → wait for **Live**. Meta's webhook check (4d) calls the API with the
verify token, so the API must be running with it first.

### 4d — Point Meta at the API

WhatsApp → **Configuration** → Webhook → **Edit**:

| Field | Value |
|---|---|
| Callback URL | `https://servicedesk-api-ss2d.onrender.com/api/whatsapp/webhook` |
| Verify token | exactly what you put in `WHATSAPP_VERIFY_TOKEN` |

**Verify and save.** Then on the same page → Webhook fields → **Manage** →
subscribe to **`messages`**. Nothing else.

**Then attach the app to the account — Meta's UI skips this.** The Quickstart
subscribes Meta's own "Test the API" app to your WhatsApp Business Account,
not yours, so nothing is delivered until you run (values from API Setup):

```
curl -X POST "https://graph.facebook.com/v22.0/<WHATSAPP_BUSINESS_ACCOUNT_ID>/subscribed_apps" \
     -H "Authorization: Bearer <ACCESS_TOKEN>"
```

`{"success":true}` means done. Check with the same URL as a GET — your app's
name must appear in the list.

### 4e — Test

From your verified phone, WhatsApp the **test number**:
> my payment was deducted but the order is still pending

A reply naming `SD-nnnn` arrives within a few seconds. Send `STATUS`. Log in
as `priya.agent@servicedesk.ai`, reply from the web app → it lands on the
phone.

**If nothing comes back:** admin → **WhatsApp** in the sidebar shows every
inbound message and the exact error on the outbound.

### 4f — The token expires in 24 hours

The temporary token from API Setup dies a day after you generate it — likely
**during your review** if you set up the night before. Two options:

- **Simple:** on the morning of the review, API Setup → **Generate** again →
  paste into `WHATSAPP_ACCESS_TOKEN` on Render → Save (2-minute redeploy).
- **Permanent (recommended, ~5 min):** https://business.facebook.com/settings
  → **Users → System users → Add** (name `servicedesk-api`, role Admin) →
  **Add assets** → Apps → your app → Full control → **Generate token** →
  select the app, expiry **Never**, permissions `whatsapp_business_messaging`
  and `whatsapp_business_management` → copy it into `WHATSAPP_ACCESS_TOKEN`.

## Step 5 — Keep it awake for the review  (~3 min)

Render's free API **sleeps after 15 min idle** and takes ~50 s to wake. Do
not let this bite you in front of the panel.

1. **https://uptimerobot.com** → free account → **Add New Monitor**.
2. Type: HTTP(s). URL: `https://servicedesk-api-xxxx.onrender.com/api/health`.
   Interval: 5 minutes.

And **open the app 5 minutes before you present** anyway.

## The demo, in order (~7 min)

1. Open the **live URL** in the browser. *"Deployed on Vercel + Render + managed Postgres."*
2. **WhatsApp from your phone**: send a complaint → show the auto-reply arrive.
3. Web app as **agent** → the ticket is in the queue, already classified.
4. Click the ticket → **AI panel → Generate draft → Insert → edit → Send**.
5. **Phone**: the agent's reply arrives on WhatsApp.
6. **Phone**: send `STATUS` → bot lists the ticket.
7. Web app as **admin** → dashboard (live numbers) → **WhatsApp console** (message log).
8. Open `/api/docs` → Swagger. *"Generated from the validation schemas."*
9. Show GitHub → green CI badge.

**Do not show:** landing page, profile page, category editing.

## If something breaks during the demo

| Problem | Do |
|---|---|
| Page loads slowly / 502 | Free tier woke up — wait 50 s, refresh |
| Login fails with a network error | CORS — step 3, check the origin has no trailing slash |
| WhatsApp reply doesn't come | Admin → WhatsApp console → read the error |
| Error mentions OAuth / token (code 190) | The 24 h token expired — step 4f |
| Meta says recipient not allowed (code 131030) | Add that phone under API Setup → To → Manage phone number list |
| Everything is on fire | `docker compose up -d` locally and demo from `localhost:8080` — say so openly |
